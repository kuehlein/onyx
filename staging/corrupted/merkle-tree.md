**Second-preimage attack on naive implementations.** If internal nodes and leaf nodes are hashed with the same domain, an attacker can present an internal node as a leaf, fabricating a valid-looking proof for a data element that was never in the tree. Fix: prefix leaf hashes with `0x00` and internal node hashes with `0x01` (specified in RFC 6962 for Certificate Transparency). Note: Bitcoin's original Merkle tree implementation lacks this domain separation and retains this vulnerability — a hard-fork fix has been proposed but not adopted.
